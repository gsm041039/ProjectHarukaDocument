# story-work-flow — 工作流管家

## 點解要有
作者要求：每件工作都要清楚知道屬於邊件大工作、去到邊一步，AI 要帶住佢由粗到幼一步一步做，唔好「做咩都好虛」。呢個 skill 只負責**工作嘅位置、步驟同節奏**；故事內容照舊由各專科 skill 做，照舊守 layer gate、Global Dependency Protection、Draft ≠ Canon。

## 工作樹（唔另外寫一份，由現有檔案推導）
- 全作 › Act I–IV：跟 `CLAUDE.md` 嘅粗到幼 pipeline 同 `canon/_working/LAYER_MANIFEST.md`。
- 大流程：`canon/_working/` 入面嘅 tracker（≥4 個 `## Stage N — 名`），檔頭有一行 `屬於：Act I` 之類。
- 工作：`canon/_working/TASK_BOARD.md` 每行，最尾一欄「屬於」寫佢喺邊（例：`Demo 試點・場景設計`、`Act I`）。
- 步驟：`canon/_working/tasks/<工作ID>.md`。

## 步驟檔格式（網頁靠呢個讀）
```
# <工作名（白話）>
類型：task
屬於：<大流程名・步驟 或 Act>
節奏：每步停          ← 或「自動」：淨係標 ◆ 嘅步先停
衍生自：`<上層文件>`

## Stage 1 — <做咩（白話）> 〔中〕 `TODO`
- [ ] <具體要做嘅事>
- 產出：`<檔名>`

## Stage 2 — <…> ◆ 〔重〕 `TODO`
```
- 狀態只用 `TODO`／`IN_PROGRESS`／`AWAITING`／`BLOCKED`／`DEFERRED`／`DONE`。
- `◆`＝做完一定停低等作者（就算節奏係自動）。
- 份量 `〔輕〕`（落檔、更新狀態檔、整理格式、搵檔）／`〔中〕`（讀資料寫草稿、核對、總結）／`〔重〕`（設計決定、結構、入 canon 前判斷、創作候選）。網頁按 `ui_config.json` `step_models` 換 model；重同 ◆ 嘅步最低用 sonnet。
- 作者喺網頁撳嘅「停低／照節奏」「輕中重」「節奏」會直接改呢啲記號，下一步要跟最新嘅檔。

## 流程
1. **歸位（每次開工、轉工作都做）**
   - **首個動作（2026-11-02）：** 叫完呢個 skill，做任何其他工具調用之前，先歸位並出 `ui:status`；未出＝未開工。
   - **對賬（2026-11-02）：** 開工時對照步驟檔狀態同磁碟上實際檔案（產出路徑係咪存在？批次已寫但仲標 TODO？），唔一致即報告並提議同步，唔好靜靜沿用。
   - 讀 TASK_BOARD 同相關 tracker，搵呢個要求屬於邊件工作。
   - 搵到：出 ` ```ui:status `，`doing`＝白話做緊咩，`task`＝白話工作名，`work`＝工作 ID（或 `<tracker>#Stage N`）。
   - 搵唔到：喺 TASK_BOARD 開新一行（下一個未用嘅 ID、狀態「進行中」、填「屬於」），再出 `ui:status`。唔使問作者；作者唔啱會喺網頁改。
   - 兩個對話可能同時改 TASK_BOARD：寫之前重讀，淨係加／改自己嗰行，唔好重寫成個表。
2. **先出計劃（新工作或者未有步驟檔）**
   - 由粗到幼拆步驟：先定方向、再落細節；唔可以跳層（上層未批嘅，標前置條件）。
   - 每步寫清做咩、產出咩、份量、要唔要 ◆。
   - **每一層（粗層、分場、beat 清單、逐 beat）都要寫角度分析，唔係淨係最幼嗰層，唔使作者開口（2026-10-31 預設）**；每步清單頭兩項固定：①「揀相關角度（粗層 4–6 個、beat 層 10–14 個，要講點解揀）＋查返已有決定」，②「TRACE 行已寫入產出檔、`QUESTION_MATRIX.md`（寫明故事位置）、`SESSION_LEDGER.md`」。冇剔就唔可以標 `DONE`。
   - **兩種深度（對照表）：** 層內每一步＝`TARGETED`（上面個數，每個有證據＋攻擊）；**層級批核前＝`FULL`（28 角度全掃）＋獨立盲審**，由 `story-orchestrator`「Beat Layer Completeness Gate」管。批核前嗰步要放喺步驟清單，標 ◆。
   - `TRACE` 行格式：`用咗 skill｜角度模式｜揀咗角度＋點解｜跳過＋點解風險低｜核對咗原文（檔:行）｜盲審 有／無｜日期`。
   - 寫入步驟檔，然後用選項卡請作者批步驟清單（可以改）。批咗先開始第一步。
3. **逐步做**
   - 開始一步：步驟檔改 `IN_PROGRESS`，出 ` ```ui:step `（`{"work","step":"Stage N","status":"in_progress","weight"}`）。
   - 一次只做呢一步，用啱嘅專科 skill。
   - **逐 beat 工作＝入 `story-room` Beat Walkthrough Mode（H 講解次序／I Gap Scan／J 新建議／K 28 行角度表），唔准即興（2026-11-02）。** Gap Scan 即係 skill 自己搵缺口：前提對賬、範圍外功能帳、接駁表、被刪項覆核、硬約束命中、環境敘事分配（設定介紹）、功能數量、決定者、出處逐條核、亂碼、層級標記、下游依賴核對、角色檔核對、知情→行動一致性、同主題多條設定對賬——唔靠作者提醒。**只有齊晒 H.4 嘅項目先可以叫「beat 結論」，否則叫「觀察」。**
   - **先分析，後問作者（硬規則）**：每步第一件事＝①查返已有決定同上層結論（QUESTION_QUEUE、CANON_DECISION_LOG、上層文件、本步已有產出），②按步驟層級揀相關角度做分析（`TARGETED`；要點見 Angle Basis Rule／`story-room`），③分析結果寫入該步產出檔。分析完仍然只有作者先決定到嘅位，先用選項卡問，每題附一句分析結論同點解係作者嘅決定。**唔可以未分析、未查已有決定就問口味題**（例：問「牙喺邊」之前要先查有冇已經定過）；已經有答案嘅唔好重問，有矛盾先問。每次最多問 1–3 條。
   - **盤點先行、慢慢跑（硬規則，2026-10-26 作者要求，優先於上面「先分析後問」嘅細節）**：作者要嘅係你帶住行，唔係拋題畀佢揀。每一層／每一步按次序：
     1. **盤點（唔問作者）**：自己讀檔，出一頁三欄表——**已定**（每項附出處檔名）／**有矛盾**（兩邊各講乜、各喺邊個檔）／**真係未定**。呢張表係本層第一份交付。讀唔晒或者唔肯定嘅，列落「真係未定」，唔好估。
     2. **慢慢跑**：按角度一個一個（或一組 2–3 個）做，每個只出 2–3 行結論，直接寫入產出檔，邊做邊報進度；唔好一次過擲一大份草稿。作者隨時可以打斷。
     3. **最後先問**：只問「真係未定」嘅位，一次最多 2 條，附分析結論。**唔可以靜靜用預設**：作者話「繼續」＝照你建議，但要寫明「暫定咗乜、點解、點推翻」，並記入步驟檔。
     4. **清單要真剔**：步驟清單入面嘅檢查項冇做完，唔可以標 `DONE`。
   - **角度紀錄去向（2026-10-31）：** 分析結果寫入產出檔之外，仲要喺 `QUESTION_MATRIX.md` 加／更新 row，row 入面寫明佢關於邊個 Act／beat 文件同相關問題（網頁先連得到）；Beat 層文件跑 `python .claude/story_system/validate_beat_layer.py <檔>`，FAIL 唔可以標 `DONE`。
   - **版本一致性核對：** 同一層有多份文件或多批逐場設計時，逐項對照後寫嗰份有冇靜靜推翻前面已記錄嘅決定；有就列偏離登記（偏離咩、邊啲下游要重新核對），唔可以靜靜沿用。
   - **批核關卡：** 步驟要請作者批一層之前，先出覆蓋狀態行（過咗幾多角度、盲審有冇、薄格數、版本一致性結果）；未過標 `INCOMPLETE_SCAN`，只出補件卡。**補件入面 AI 自己做得到嘅（補掃角度、重核、補表、改出處）直接做，唔好列清單問作者；只有真正要作者決定先問（2026-11-02）。**
   - 做完：步驟檔改 `DONE`（要作者批先算完嘅改 `AWAITING`），清單剔返，出 `ui:step`（`status:"done"` 或 `"waiting"`）。
   - **停唔停**：節奏「每步停」或者呢步有 ◆ → 出停低卡（下面）再用選項卡問作者；節奏「自動」又冇 ◆ → 直接開始下一步。
4. **停低卡**（要具體，唔好淨係問「批唔批」）：做咗咩、改咗邊個檔（改前／改後重點）、有咩未決、下一步係咩同佢嘅份量。然後選項卡：繼續下一步／改呢步／停喺度。
5. **收尾**：全部做完，TASK_BOARD 嗰行改「完成」或者「等作者」，更新 SESSION_LEDGER；照 CLAUDE.md 更新其他 state files。

## 舊工作補掛
作者叫「幫我掛好舊工作」時：讀晒 TASK_BOARD 同 tracker，列對照表（工作 → 建議屬於邊、點解），用選項卡請作者批；批咗先寫「屬於」欄同 tracker 嘅 `屬於：` 行。逐件問要唔要補步驟檔。唔改任何故事內容。

## 界線
- 只管工作位置、步驟、節奏、狀態；唔代作者做故事決定，唔寫 canon。
- 對作者顯示嘅字唔用內部編號（ID 只放喺 JSON 嘅 `work` 同檔案入面）。

## Workbench Choices
- 🧭 歸位開工 | 用 story-work-flow：搵我要做嘅嘢屬於工作樹邊度（冇就開新工作），出狀態卡，再講下一步。{goal}
- 🧩 拆步驟 | 用 story-work-flow：為呢件工作由粗到幼拆步驟（份量、邊步停低），寫入步驟檔，用選項卡畀我批先開始。{goal}
- ▶ 做下一步 | 用 story-work-flow：讀步驟檔，做下一步，跟節奏停低或者繼續。
- 🌳 掛好舊工作 | 用 story-work-flow：讀晒 Task 板同大流程，列「屬於邊」對照表同理由，用選項卡畀我批先寫入。
- 🧐 逐 beat 慢慢講 | 用 story-work-flow 帶入 story-room 逐 beat 講解模式：就 {goal} 先讀推導歷史，Gap Scan 自己搵缺口，日常講法講畀我聽，發現標 Beat／Scene 層，提 2–3 個新建議並用同一套角度並排比較（包括現狀），落檔追蹤。
- 🐢 盤點先行慢慢跑 | 用 story-work-flow：就 {goal} 先出基本盤點三欄表（已定／有矛盾／真係未定，唔好問我），再逐個角度慢慢跑（每個 2–3 行結論，直接寫檔），最後先問真係未定嘅位。
