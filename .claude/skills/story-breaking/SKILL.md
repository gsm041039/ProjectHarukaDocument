# story-breaking — 宏觀故事創作（Story Architect）

Task:
$ARGUMENTS

## 幾時用／唔用
- 用：作者要「發展呢一幕」「呢段點行會更好」「重新構思」「有冇更好嘅安排」「幫我 break 呢段故事」，範圍係一幕或一段 Sequence、牽涉多個角色。
- 唔用：單一 beat 審查（`story-room`）、查 canon 事實（`story-source-recovery-gate`）、寫 scene／對白（`scene-lab` 等）、批核一層（`story-orchestrator` 嘅 gate）。細問題嘅候選比較仍然用 `story-solution-space-designer`。

## 同其他 skill 嘅分工（重用，唔重寫）
- 入口：作者講話經 `story-router` → `story-orchestrator`；orchestrator 見到宏觀創作要求就交過嚟，結果（DRAFT 路線＋建議）返畀 orchestrator／作者。
- 事實：需要確認 canon 就叫 `story-source-recovery-gate`；人物動機用 `story-motivation-grounding`、關係用 `story-relationship-dynamics`，只在真係需要時叫，唔逐個過一次。
- 唔受限於：28 角度 Registry、Gap Admission Gate、Existing Carrier First。呢啲係審計同修補嘅工具，會令創作偏向守住現有大綱。本 skill 嘅創意構思標 `OPPORTUNITY／候選`，唔需要先證明「有 gap」。
- 唔取代：層級批核仍然要 orchestrator 嘅 Completeness Gate；落檔入 canon 仍然要 `story-writeback` ＋作者批准。

## 做法

**1. 先讀齊再創作。** 目標幕大綱、前後幕大綱、出場角色嘅角色檔（唔好淨睇大綱）、相關決定記錄、粗綱同 Brief。未讀角色檔就唔准提出涉及該角色嘅事件。（教訓：只憑大綱提方案，結果同角色已有設定衝突。）

**2. 分三堆，並講明。**
- **鎖死**：決定記錄入面有作者明確確認（記日期／出處）。大綱寫咗但冇確認紀錄嘅，唔算鎖死。
- **可動**：文件有寫但非作者確認，或者兩份文件互相矛盾。
- **未定**：標咗 btd／作者未決定。
同時列出發現嘅矛盾，用「有標記嘅創作假設」繼續推演，唔使停低等作者。

**3. 搵未充分發展嘅位（用簡單測試，唔填表）。**
- 「因此／但係」測試：將主要事件逐對連起嚟，只接得上「然後」＝冇因果。
- 主動性：每個主要角色喺呢段有冇做過一個有代價嘅選擇，定淨係被事件推？
- 互動：各角色線有冇互相改變對方，定各自孤立？
- 入口出口：上一段點樣交落嚟、呢段點樣交落去？有冇懸而未答。
- 形狀：張力有冇升降，有冇希望、勝利或真暖嘅位；有冇連續同質（例如一路下沉、揭露連環、同一地點重複大場面）。
- 玩家：玩家喺呢段做咩，選擇有冇後果。

**4. 創作至少兩條完整路線。**
- 兩條都由「呢段必須去到嘅已定終點」倒推，揀唔同嘅**引擎**（唔係換皮）。一條可以保留幕綱，但要寫到最好；一條可以挑戰重要安排。唔准為襯托其中一條而寫漏洞百出嘅另一條。
- 每條 6–10 個主要事件，用人話講：起點狀態、事件間因果、角色目標同心理變化、角色之間點互相影響、玩家做咩、終點狀態。唔逐 beat 填表。
- 盡量用角色自己嘅習慣、已有伏筆、已有矛盾做機制（由人物推出事件，唔係由主題意象砌事件）。新構思標（新）。
- 如果要改鎖死嘅決定，列出改動代價，但代價唔等於創作價值低，分開講。
- 容許安靜、日常、細膩嘅事件；唔好為咗刺激盲目加衝突或反轉。

**5. 先寫好，再攻擊自己。** 每條路線寫完，逐條問：
- 有冇刻意催淚、為迎合主題而犧牲真實感？
- 人物咁做可唔可信？有冇靠角色標籤跳結論？
- 有冇太巧合、缺鋪墊？
- 事件係咪「因此／但係」，定「然後」？
- 有冇重複同一種場面或同一種揭露？
有問題就改版，包括自己之前提過嘅方案。

**6. 用劇情比較，唔用符合度比較。** 用具體事件證明：人物更可信？因果更緊？有冇意想不到而回頭合理？節奏、主題、玩家體驗？「符合原設定」「改動少」唔係優勢理由，成本另外列。主動講邊個最值得探索，亦可以建議混合。唔假設作者想要邊個答案。

**7. 重大決定交返作者。** 改鎖死決定、改一幕方向、改角色生死或結局＝作者決定：用 `story-co-design-discussion` 嘅白話格式＋AskUserQuestion。其餘創作假設自行推進並標明。唔擅自改寫 canon；作者要落檔時，寫成 `canon/_working/story_construction/` 下嘅 DRAFT 檔（檔頭寫「衍生自／依據」），再按現有 gate 處理。

## 輸出（精簡、人話、冇內部編號）
第一段兩句結論 → 研究對象＋鎖死／可動／未定＋矛盾 → 診斷 → 路線 A、B（各 6–10 事件）→ 比較 → 建議探索方向＋仲唔肯定嘅位。唔出 28 行表格。仍然跟 `Plain-Language Explanation Rule`：講清發生咩、點解、代價、放棄咗咩。

## 方法來源（已驗證 vs 待測）
- 已廣泛使用：「Therefore／But」因果測試（Parker & Stone 常被引述）；Writers' room 逐 beat 推演、由幕尾倒推（ScriptMag, Writers' Room 101）；Sequence Approach（Frank Daniel／Paul Gulino：每段自成小故事、未解衝突推動下一段）；A/B/C 線交織（writers' room）。
- 來自本專案兩次實驗，仍需更多案例測試：鎖死／可動／未定三分、以角色習慣做機制、對自己方案嘅攻擊清單、兩路線公平規則。
- 推論未直接驗證：reverse outline（發展編輯）等同「因此／但係」逐對檢查。
- 外部現成 Claude skills（見交付報告）只作參考，未安裝；本 skill 係抽取做法，唔係複製。
