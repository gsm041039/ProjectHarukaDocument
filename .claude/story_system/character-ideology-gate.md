# Character Growth + Ideology Theme Gate System

呢個 gate system 係 story workflow 的一個正式控制層。

任何 story-base / full-outline / act-outline / beat-sheet / major event design 任務，都必須通過以下三個 gate 的檢查。三個 gate 唔係選做，唔係補充，係 mandatory。

**核心原則：**
- 角色成長 ≠ 主題表達
- 主角點變 ≠ 作品立場
- 群體 / 制度唔係只係背景，佢哋係主題立場承載者

---

## ⚠️ Gate A：Character Growth Gate

**觸發條件：** 任何 story-base / full-outline / act-outline / beat-sheet / major event design

**唔可以只講感受或弧線方向。必須落表，每欄都要有答案。**

### Output Contract — Gate A（最低必須輸出）

每個主要角色至少完成以下欄位：

| 欄位 | 說明 |
|---|---|
| **起點狀態** | 故事開始時角色的心理/行為狀態 |
| **核心傷口** | 最根本的未癒合創傷或失落 |
| **Coping pattern** | 佢慣常如何保護自己 / 避開痛苦 / 防止重複傷害 |
| **主要欲望** | 表面上最想要的東西 |
| **主要恐懼** | 最深層最不想面對的東西 |
| **False solution** | 佢誤以為能解決問題的方法（通常是 coping pattern 的延伸） |
| **Change trigger** | 真正令佢改變的關鍵事件或 decision moment |
| **Ending state** | 故事結束時的狀態（唔一定係「成長」，可以是崩潰/接受/倒退/部分改變） |
| **Cross-act progression** | Act I / II / III / IV 各在哪個心理狀態 |
| **Growth type** | collapse / acceptance / inversion / self-definition / failure / partial change |
| **Status** | AC（Author Confirmed）/ SS（Source Supported）/ BK（Blocked） |

**禁止：** 只用幾句話描述角色弧線而冇落表。

---

## ⚠️ Gate B：Ideology / Theme Stance Gate

**觸發條件：** 任何主要角色、反派、關鍵副角色、重要群體、制度、世界機制代表者

**每個 entity 對核心主題的立場，必須明確落表。唔可以留空任何一欄。**

### Hard rule for Narrative Validation Level

> 故事對一種 stance 的處理，不等於角色本人對該 stance 的理解。

AI 必須分清楚三件事：
1. 角色**自己以為**自己信咩
2. 故事**實際揭示**佢真正信咩（通過後果、選擇、矛盾）
3. 作者希望觀眾**最終如何看待**呢種 stance

三件事可以完全唔同。

### Output Contract — Gate B（最低必須輸出）

每個主要 entity 至少完成以下欄位：

| 欄位 | 說明 |
|---|---|
| **Entity** | 角色/群體/制度/世界力量的名稱 |
| **Theme topic** | 呢個 entity 所代表的主題切面（可以多個） |
| **Stated belief** | 佢自己以為自己信的是什麼 |
| **Actual belief** | 故事揭示佢真正信的是什麼（通過行為、選擇、後果） |
| **Method of dealing with pain / fate / love / freedom / responsibility** | 佢的實際處理方式（行為層面，唔係口號） |
| **What this stance promises** | 佢的立場許諾了什麼（自我或他人） |
| **What this stance hides** | 佢的立場遮蔽了什麼（代價、盲點、恐懼） |
| **What this stance costs** | 真正的代價是什麼 |
| **Mirror / oppose** | 哪些角色/群體與之相似 / 對立 |
| **Where it appears** | 出現在哪些 acts / beats / events |
| **Story's treatment** | 故事 validates / complicates / rejects / transforms 呢種 stance（唔可以留空，必須選一個或多個） |

---

## ⚠️ Gate C：Theme Conflict Gate

**觸發條件：** 任何 major event / act / beat

**主題唔係靠說教表達，而係靠立場衝突 + 後果表達。唔係角色「感受到咩」，而係「哪兩種立場真正交鋒，交鋒完產生什麼後果」。**

### Output Contract — Gate C（最低必須輸出）

每個重要事件 / act / beat 至少完成以下欄位：

| 欄位 | 說明 |
|---|---|
| **Theme question at stake** | 呢個 beat / event 涉及哪個核心主題問題 |
| **Stances in collision** | 哪兩種（或幾種）立場在此交鋒（引用 Gate B entity 名） |
| **Collision mechanism** | 衝突係點被戲劇化的（行為 / 選擇 / 拒絕 / 後果 / 對比 / 沉默）|
| **Outcome / consequence** | 撞完之後發生咩，有冇結果 / 後果 |
| **Audience understanding target** | 觀眾應感受到 / 理解到什麼（唔係「氣氛壓抑」，而係對主題嘅具體認識）|
| **Later payoff** | 對後面哪條 payoff 線有影響；這裡的選擇點有冇提前透支後段情緒 |
| **Status** | 係咪有足夠事件承載呢個衝突，還是只停留在角色內心或對白？ |

## 三個 Gate 的落表規則

- **Gate A 結果** → 寫入 `canon/_working/story_construction/INDIVIDUAL_CHARACTER_GROWTH_TRACKER.md`
- **Gate B 結果** → 寫入 `canon/_working/story_construction/IDEOLOGY_THEME_STANCE_MATRIX.md` 及/或 `GROUP_WORLDVIEW_CONFLICT_MAP.md`
- **Gate C 結果** → 寫入 `canon/_working/story_construction/THEME_CONFLICT_EXPRESSION_TABLE.md`
- **Gate 分析過程中的推理** → 寫入 `canon/_working/REASONING_LOG.md`
- **Gate 觸發的角度掃描（angles 13–18）** → 寫入 `canon/_working/story_construction/QUESTION_MATRIX.md` 對應 row

唔可以只喺 chat 完成分析。所有 gate 結果必須落檔才算完成。

---

## 三個 Gate 與 CONTROL_OBJECTIVES_MASTER.md 的關係

三個 gate 產出的表格係**分層分析工具**，唔係控制總表。

**`CONTROL_OBJECTIVES_MASTER.md` 係最高層控制視角，記錄全作控制任務狀態：**
- 哪條 growth line 需要在哪個 act 到達哪個狀態
- 哪條 reveal / stance 線幾時需要開始令觀眾有感
- 哪種 stance 靠主線定 side content 承載
- 哪條衝突係咪已有事件承載

每次完成 Gate A / B / C 後，要檢查 CONTROL_OBJECTIVES_MASTER.md 係咪需要更新。
