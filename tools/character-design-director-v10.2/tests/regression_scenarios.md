# v9.6 回歸測試｜專門測「講得到但未做得到」

> 以下係**通用匿名情境**，唔係任何正式角色 brief。每次測試喺生成前保存 PRECOMMIT，生成後保存 ACTUAL。此文只定義驗收要求，**唔代表模型已跑過實際美感測試**。

## T01：帽後有兩條唔同色嘅髮帶

**輸入**：現有角色有深色帽、金色頭髮、青綠上衣、梅紫下裝；帽後一條灰綠、一條酒紅髮帶。用戶要求全面改善。

**必須出現喺出圖前記錄**：
- 見到「帽後兩色」並分別指出和全身配色係呼應、意外對比，定係未證實沿用；唔可以只描述帽子有裝飾。
- 至少兩條可能方向：保持對比但優化明度／色位；或者改到同主要色塊更一致；兩條都要有可能**失去原版性格**嘅理由。
- 唔准單純因為「配色一致」判後者必勝。

**FAIL**：先改上衣，生成後先評論髮帶配色；或者聲稱原配色肯定係作者意圖。

## T02：設計變得更簡潔，但魅力下降

**輸入**：候選刪去局部花紋，符合指定 TV Anime 線條負擔，但整體輪廓更普通。

**必須出現**：`Production Fit = possibly better`；`Design Gain = not established/possibly worse`；並**喺下一個設計假設**嘗試改善人物獨特性，而唔係繼續盲目減 detail。

**FAIL**：因為動畫方便就稱「全面升級」；或者只回答「不合格」而冇提出下一個視覺策略。

## T03：整體比例改動有理，但圖像模型失控

**輸入**：預先鎖定一個上衣輪廓方案，生成模型擅自加入袖條紋、內搭層，同輸出設計資訊板。

**必須出現**： `EXECUTION=DRIFT`、原來形體假設是否仍可獨立保留嘅判斷、清楚嘅局部改圖 spec。不能把未授權裝飾列成原方案嘅設計意圖；同類偏移兩次停試。

**FAIL**：貼上資訊板並寫「已成功改善」；或者因為畫錯就話原本設計假設必然錯。

## T04：作者要求華麗、複雜的魔法角色

**輸入**：Art Direction 指明高裝飾美術，固定角色身份；正在探索華麗但有主次嘅服裝。

**必須出現**：合理容許高裝飾，分析焦點／密度集中區／動作成本，唔預設「全部改簡」；同時避免每個部位等密度堆疊。

**FAIL**：把「零新增裝飾」變成永久硬限制，或者所有方案都只減圖案。

## T05：只有正面原稿，背部係 UNKNOWN

**輸入**：只提供一張正面角色設計圖，要求創意改進。

**必須出現**：背面配色／固定點標 UNKNOWN；如果必須設計背面，清楚標示為 `NEW PROPOSAL`，唔冒充原稿已有。

**FAIL**：憑空聲稱原稿背面某件配件或頭髮顏色一定係咁。

## T06：只要求局部修正

**輸入**：作者指定「只調整袖口，其他不可改」。

**必須出現**：仍做簡短全身關係檢查，但只就袖口提出一個方案，冇必要強行三候選；所有非袖口變更標 DRIFT。

**FAIL**：套用「必須有大幅設計突破」所以改咗半套衫。

## Test verdict 建議

對每個案例記錄 `PRECOMMIT_EXISTS / CHECKLIST_COMPLETE / RESULT_AUDITED / ACTUAL_IMAGE_COMPLIANCE / HUMAN_APPEAL_REVIEW`。書面通過**只代表流程可以執行**；真正改善美感須真人同條件 A/B 比較、動畫生產人員回饋或相應測試。唔用假分數證明 Skill 成功。
