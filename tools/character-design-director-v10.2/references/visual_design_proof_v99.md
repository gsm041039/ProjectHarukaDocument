# Visual Design Proof v9.9 — 可見嘅設計證據，取代空泛理由

## 呢份文件唔係另一份「寫報告」任務

目標係令設計師／AI 喺正式生成前，用非常粗略嘅視覺證據睇到自己究竟改咗**乜嘢結構關係**。只要求識比較，不要求靚。避免把信息圖報告送入圖像工具。

## 兩階段圖像：Concept Proof ≠ Final Character Render

**Concept Proof**（出正式設計圖前）：可用 SVG、簡筆草圖、平塗色塊、剪影輪廓對比或原圖局部手工標註，低成本、可回退；唔應直接用 full anime image generation 當概念門檻。如果作者要求「先畫出方案畀我睇」，亦要標 `SKETCH / UNVERIFIED`，唔係正式成品。

**Final Render**（門檻通過後）：高品質正背設定圖；使用原圖作身份參考，跟 precommit 嚴格執行，毋須再將設計報告混入圖面。

## 每個候選需要一張同尺度比較圖

每張圖至少有：
- `BEFORE (baseline)` 同 `AFTER (candidate)`，同角色／同姿勢／同視角／同縮放；如果原版係完整角色圖，可以用簡化輪廓重畫，但註明「概念描畫、非精確量度」。
- 同一張證據上畫出**正面 + 背面**（局部任務如只有一側，至少寫明另一面保留／預計影響）。
- 最重要嘅**比例錨點**：如 `頭頂、肩線、袖最闊處、衣擺、裙腰、裙擺、腳踝`，畫出 before/after 嘅相對上下關係。唔應使用虛構數值；可以寫「原衣擺＝蓋住裙腰 → 建議＝略露裙腰」。
- **輪廓外緣**：至少能看出大形有冇換；若只係色彩策略，形體可以 `KEEP`，但要比較色塊位置同面積。
- **色彩分區**：前／背主色與輔色在哪裏；如果全部保留，要有理由。只要近似色票，唔要無來源精確 HEX。
- **穿搭機制**：件衫係點着／綁／疊／披／收口；KEEP 就要說明「穿法本身值得保留」而唔係偷偷冇改。
- **觀眾首讀方向**：用 1–2 個標記指明關鍵焦點從邊到邊，點樣增加**此角色**嘅親和力、俐落感、稚氣、神秘等已確認氣質；並寫會犧牲乜。

**絕對唔接受：** 同一個剪影只換標題／顏色標籤、兩張圖只係新增線條、只畫一件 Hoodie、只把三視圖塞進信息板、甚至只喺設計評論寫「腰線改善」。

## 用設計元素而非描述去構思

| 構思面向 | 比較問法 |
|---|---|
| 全身比例 | 頭髮量塊 vs 袖量 vs 下裝展開；腰線與上下身長度；襪鞋重量係咪平衡 |
| 剪影／節奏 | 何處寬、何處收、何處留白、前後邊緣係水平定斜向 |
| 配色 | 是否可以把某個點綴從無必要嘅地方搬去真正焦點？原本細小配色反差失去咩 |
| 穿法與個性 | 綁、露、披、袖口捲起等係咪角色自己會選擇嘅行為，改完仲係同一個人嗎 |
| 動畫細節 | 需要跨幀追蹤嘅固定線、紋理、小件數量有冇增加；可以簡化而不犧牲識別嗎 |

## 選案硬測試

- 問 `唔睇標註，只睇比較草圖，可否指出有實質差異？` 若唔得，`REWORK`。
- 問 `把候選放返全身，頭／身／裙／鞋係咪仍然共同服務角色魅力？` 局部更靚但整體變普通，`REWORK`。
- 問 `呢個係凈收益定移花接木？` 如果原稿優點被犧牲，替代方案有無足夠獨立收益；回答不了就 `REWORK`。
- 問 `即使動畫易畫咗，角色有冇變得更有特點？` 只改善成本不能稱設計升級。
- 問 `有冇作者未批准嘅新符號、角色性格變化或過密 details？` 有就移除或重新取得方向授權。

## 視覺證據嘅儲存

推薦 `candidates/<round>/proof_A.svg`、`proof_B.svg` + `preflight.json` + 最終另存 `render.png` 同 `post_review.md`。SVG 需包含實際繪製元素（非空白畫布），不要用絕對路徑依賴本機另一人無法取得嘅檔案。程式只能檢查存在和格式，**唔識判斷草圖究竟反映設計改良**。為免重複生成成本，可以先喺對話直接展示同等結構嘅簡化比較 SVG，再另存圖。
