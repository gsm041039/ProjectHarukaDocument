# Change Rationale Gate（v9.2.1）：設計改動嘅理由要先於圖像

## 由改版測試歸納嘅常見失敗模式

以前錯誤：未列出明確問題就生成滿版重複圖案、貼章、裝飾條紋；呢種設計係以「細節數量」充當「完成度」，又因為設定紙排版更華麗而誤判角色更好。最嚴重係出完圖冇交代**邊個改動解决咗乜**。呢個係流程失效，不可重複。

## 兩個分離問題

- **設計變好未？** 看角色本身同原稿比較：比例、負形、剪裁、穿法、色塊節奏、角色獨特性、材質邏輯；不可單靠渲染質素、版面、文字、表情差異。
- **出圖漂亮未？** 看線稿、色彩、排版、細節。出圖精美但角色冇真正改進，應判「畫得靚／設計未證實」。

## Pre-render Gate（每次 ENHANCE 必做）

1. **原版觀察 O（2–4 個）**：只寫圖像真係有嘅內容，並指出 2–3 個應保留特徵。
2. **阻礙 D（最多 2）**：用形體／穿法／主次「關係」描述，唔用「太普通」結案。冇合理阻礙就明講可以原樣保留。
3. **候選 H（至少 A/B）**：A/B 主要機制需不同；已確立嘅身份錨兩版都保留。
4. **選擇 S（1 個）**：點解呢個改動幅度最適合；另一版點解暫不做。
5. **Change Ledger（3–5 條）**：每條最少五欄 `原稿現象/可畫改動/預期效果/代價/對照失敗條件`；「無法說服自己」嘅改動取消。
6. **Detail Budget（非硬性裝飾總量配額）**：先盤點原本嘅高對比焦點，任何新 logo/貼章/條紋/印花問「係咪取代咗其他元素？有冇搶主角？」。優先**重排、剪裁、留白、合併**，而唔係加法。高裝飾型角色允許高細節，但要有清楚理由。
7. **生成需求**：指明「以作者原版為唯一身份參考、上次 AI 候選只作失敗例子」，交代同角度、正背、灰白無花背景、唔虛構個人資料；模糊設定毋須強行寫字。

## Post-render Audit（生成後絕不省略）

- `HIT`：對照圖確實改到；指出可見部位。
- `MISS`：圖冇體現；唔假裝已做。
- `DRIFT`：出現原設計未授權變化；記下、視嚴重程度重畫。
- `CONFOUNDED`：新版本因姿勢、表情、光照、比例、渲染水平唔同，**無法判斷設計**。
- `HUMAN_TEST_PENDING`：美感判斷係設計主張，未經真人盲測唔可聲稱已證。

**禁止**：聲稱一個角色更具商業成功率而冇證據；擅自補年齡生日；把更華麗的 sheet 當更好看；靠疊加同一 motif 十次，或者喺新圖完成後臨時拼湊理由。冇提高就講冇提高。

## 最短對用戶交付

「我改咗 X，因為原稿 Y 造成 Z 嘅視覺感受；咁會犧牲 W。圖上可見 X / 未能做到 X。原版仍較強係 K。呢個係候選，等你批准。」

## v9.1 實戰新增：輸出類型鎖

如果任務係「幫角色改圖」，請先輸出**一張角色本體改版稿**，而唔係設計流程 infographic、A/B/C 報告版面或自評 scoreboard；文字理由應存在文件／文字回覆，唔由 image model 自行撰寫。相同 DRIFT 失敗 **兩次**之後停手，狀態 `NO_ACCEPTABLE_CANDIDATE`，保留原稿與可執行的受控編輯 prompt。呢個可以避免連續生成越來越偏離原稿而後硬要合理化。


## v9.2.2｜Necessity Gate（通用）

在 Change Ledger 前先問：

- 原稿具體觀察到咩？係實證定美術假設？
- 目標觀眾／用途會受咩影響？
- 如果完全唔改，會失去乜？若冇明確代價就保留。
- 改法可唔可以更小？會唔會失去原版已經好嘅地方？
- 新圖是否按授權變更？未證明更好不准寫 `IMPROVED`。

合法結果包括 `KEEP ORIGINAL / EXPLORATORY ALTERNATIVE / TEST MORE / NO_ACTIONABLE_PROBLEM / NO_ACCEPTABLE_CANDIDATE`。


## v9.2.3｜Wearing Identity Gate（服裝改版必做）

在提出服裝大改動前先跑 `references/wearing_identity.md`：
1. 記錄原稿 **着法、綁結、披搭、開合、袖量、鬆緊、不對稱、露出層次**；查清楚佢哋構成嘅視覺關係。
2. 指出方案有冇**抹掉原本嘅穿搭身份**，若有，列出真實代價並同 `KEEP WEARING` 對照。
3. 若只因「更整齊／更對稱／更像標準校服」就要改穿法，直接退回重新論證。
4. 有角色專屬 brief 授權可以重新穿搭；**本規則唔固定保留任一着法**，只要求先評估，後取捨。
5. 出圖後增加 `Wearing audit`，實際對照着法係保留、授權更改、未授權偏移或無法確認。


## v9.3｜創作探索 Ledger 補充
當作者要求真正重新設計而非修 bug，可填 `Creative Opportunity` 而非原版缺陷，必須寫 Design Thesis、主導造型決策、可見差異與風險；唔好虛構問題，亦唔以小修小補充當重大升級。


## v9.4｜Decoration Bias Check 補充

凡係有新衣服線條、圖案、滾邊、扣帶、掛飾，出圖前先用 `references/decoration_bias_check.md` 五問；出圖後對 `PLANNED / ACTUAL`。**不能以「加細節」當改善，亦不能一律禁止符合 brief 嘅華麗設計。** `CREATIVE ALTERNATIVE` 必有零新增裝飾方案作比較；`REFINE` 及指定紋樣任務容許註明豁免。
