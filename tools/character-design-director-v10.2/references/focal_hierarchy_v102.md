# v10.2 — Visual Accent & Focal Hierarchy（通用角色色彩創作）

## 唔係「每個角色都要點綴色」，而係「每次配色都要考慮視線」

**配色**唔只係主／輔色比例，亦係不同部件嘅面積、相鄰關係、對比位置同觀眾視線路徑。角色可以靠少量高對比色有記憶點，亦可以完全唔加新色，靠黑白面積、髮色、剪裁同質感建立同樣清楚嘅層次。唔好將用色公式寫成通用規則。

## 何時執行

- PHASE 1 / 2：快速閱讀全身焦點，建立基本設計假設，唔使深入局部選色。
- PHASE 4 / 5：有發展中嘅全身 concept（`DEVELOP` / `SHORTLIST`），需要改善吸引力或決定主色分配時，使用完整「Focus First」設計迴圈。
- 特別係用戶明確要求「主色要改成 X」：主色只係角色身份約束；**未驗證焦點前，不要直接開 P1/P2/P3 任意主色比例選擇題**。
- `REIMAGINE` 必須尊重已選中該路線嘅服裝整體主張；不得拿舊原稿嘅色塊／衣物偷換進候選。`AMPLIFY` 則要認真保留原版既有魅力。

## 1. FOCAL MAP：目前真正睇到嘅焦點

至少描述三層（沒有三個明顯焦點可記 `none / too diffuse`）：

| 層 | 對應問題 | 證據類型 |
|---|---|---|
| 第一眼 | 視線最先落在邊？係臉／眼／髮、衣領、裙，定高亮物？ | 圖像目視；必要時同尺度縮圖 |
| 第二眼 | 視線被乜帶去第二處？（領口、包袋、腰線等） | 相鄰色塊、明暗、輪廓及造型關係 |
| 第三眼 | 視線停留／回流去邊？ | 全身節奏、上下平衡、配件 |

區分 `(OBSERVED)`、`(HYPOTHESIS)`、`(AUTHOR FEEDBACK)`，避免未有 viewer test 就聲稱客觀注意力測定。

## 2. FOCAL INTENT：先決定目的，之後決定手段

一句講清楚：要突出乜、點解啱呢個角色／服裝用途；保留已成立焦點；識別所有不應被搶嘅區域。

例如「低調但自然有明星氣質」可以容許臉做第一焦點，少量衣領或者上胸部件做第二焦點，但**唔代表一定要將個領口染成金黃／紅色**；先定目的同位置，先研究色相。

## 3. 對比機制：比較真正唔同嘅方法

至少考慮以下兩種有意義嘅方案（不要求都出圖）：

- **局部小面積高對比**：例如衣領交界、小面積翻面、帽邊／腰側配件；可比較色相、冷暖、明度、飽和度、相鄰基底。要講出**點解係呢個位置、預期吸睛但不搶戲嘅原因、可見嘅牺牲**。
- **無新增高彩度色**：靠明暗、留白面積、布料材質、輪廓或已有顏色嘅重新定位做到焦點；允許完全不加點綴色。
- 需要時可以研究第二種對比位置，或者高對比嘅色只喺動作時露出。決定前先問「點樣影響視線」，而唔係「邊隻色靚」。

**禁例**：為咗交 checklist 而喺帽、胸、手腕、裙、鞋齊齊加一個高飽和裝飾；盲目追 `5% accent`；冇圖就虛報 ΔE、比例或眼動結果。

## 4. 受控探索與作者回饋

1. **先交當前 focus map + 建議對比目標**（一般短兩三段），只問作者一個有意義嘅問題，例如「想突出臉旁，定腰線？」；作者亦可以請 AI 自行判斷。
2. 選定焦點意圖後，先構想 2–3 個落在不同位置／採不同機制嘅方案；未選定顏色前**唔硬編 hex**。
3. 畫圖：用**同一份已認可嘅服裝構造**、相近姿勢、臉同頭髮、光照、圖像完成度；先固定主色同已批准部件，只改焦點變量。禁用多段文字 infographic 代替正常概念圖。
4. 比較：全身第一眼、角色氣質、偶像「低調」可信度、顏色有冇幫到眼神而非搶走佢、視線有冇主次；細節密度留到 Production。
5. 作者 partial approval：記 `APPROVED_PART` 例如只批准配色，不批准新配件；保留上輪而唔將新圖一整套當定稿。

## 通用決策紀錄最短格式

````text
Concept / locked elements: ...
Current observed focus: first ... / second ... / third ...
Intended focus: first ... → second ... → return ...
Contrast option A: small local accent at ... / expected gain ... / risk ...
Contrast option B: no new chroma, value/material or topology at ... / expected gain ... / risk ...
Decision: explore ... / defer ...; unresolved ...
````

**程式只驗證文字欄位有齊，不能證明焦點路徑、色彩美感或注意力效果。**
