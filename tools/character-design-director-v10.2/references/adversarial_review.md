# B｜Adversarial Audit：唔幫自己嘅設計搵藉口

## 先審 Brief，後審好唔好睇

審查出發點：作者批准咗啲乜、素材係咪 canon、有冇故意保留嘅奇怪比例、有冇功能／媒介約束。提出新版本之前，寫低原版最有力嘅 2–3 點，避免只識搵缺點。

## 每次都要做嘅四個挑戰

1. **反方向挑戰**：「如果我反對呢次改版，最有力嘅理由係乜？」例如改咗更乾淨，但失去咗角色原有張力；若反對理由成立，留原版。
2. **其他解釋**：「改善係因為剪裁、姿勢、上色、光照定構圖？」同條件未控就唔推因果。
3. **錯誤目標**：「我係咪優化縮圖／對稱／低細節分數，卻犧牲真正美感？」唔把 proxy 當目的。
4. **可推翻條件**：「乜嘢證據會令我承認方案較差？」例如同姿勢並排，5 秒首眼更分散；側面髮飾撞肩；角色身份混淆。

## 成對比較（原版 vs 候選 A vs 候選 B）

先明確**觀察情境**：同姿勢、角度、表情、光照、背景、人物佔高、畫面用途；有變項無法控制就記 `CONFOUNDED`，唔好用 IoU 或面積百分比充當設計好壞。外輪廓要拆人體、衣物、頭髮、頭飾、持物、姿勢；頭像以頭部為錨（v8 G14/G15）。

用比較語言，而唔係假精度評分：

| 維度 | 判斷問題 | 答案 |
|---|---|---|
| First-glance appeal | 邊版視覺焦點更清楚／更吸引？目標觀感有冇到？ | A 較好／原版較好／相近／未驗；講證據 |
| Character-specificity | 視覺改動是否強化此人嘅已知選擇與處境？ | 同上 |
| Distinctiveness | 與最近似 cast／相似商業設計會唔會混？ | 同上 |
| Visual craft | 形狀節奏、材質、疏密、負形、色彩協調／反差是否更成熟？ | 同上 |
| Practical use | 正側背、動作、製作工數或使用情境有冇更差？ | 同上 |

**唔機械加權平均。** 若硬鎖違反，直接候選 `BLOCKED`；若兩版互有強項，可以 `TEST MORE`，唔強迫唯一勝者。

## B1｜Aesthetic audit（有理據但唔假裝客觀）

將「靚／唔靚」拆成 4 個可觀察嘅關係：
- **焦點 vs 噪聲**：視覺第一眼有冇被多個同等強烈元素拉扯？
- **節奏 vs 平板**：大中小、直曲、鬆緊、厚薄變化有冇清楚嘅主線？
- **一致 vs 驚喜**：作品語言內有冇有意義嘅破格，定係千篇一律？
- **人物 vs 泛用**：嗰個記憶點係咪真係呢個角色獨有？

寫成：「我判斷 X 比 Y 好，因為比較圖見到 __，但可能有 __ 代價」，而唔係「AI 評 92 分所以成功」。

## B2｜V8 規則自我審查

| 風險 | v9 處理 |
|---|---|
| 規則由成功案例歸納 | **Selection bias**：記錄失敗版本、未有結果同反例；「知名成功」唔係因果證據 |
| 14 方向投票高度一致 | **Correlated reviews**：共用資料同框架嘅投票唔等於 14 個獨立人類實驗 |
| `CONFIRMED` 字眼 | 只代表 v8 定義內有案例支持；不當成美感、觀眾辨識／銷售效果證實 |
| 64 px、灰階、輪廓 | 只喺對應媒介／brief 有用，唔拿來否決近讀母題或高細節造型 |
| 角色意圖與心理 | 外觀只證可見關係；顏色、幾何與穿法無法診斷性格／創傷 |
| 圖像統計 | 影像遮罩、姿勢、裁切／鏡頭、道具與光照要配平，寫未知與限制 |
| 商業判斷 | 「好賣／有記憶點」需要受眾／市場實測；不能由單張圖下斷言 |

## B3｜Human Feel validation：有條件先做真人測試

如有適合嘅受眾、授權同實際樣本，測試可以按嚴謹程度選擇：

1. **First-impression**：隨機順序、同尺寸展示、短時間第一眼，先問開放式「見到乜？感覺點？」唔先提示目的。
2. **Pairwise preference**：原版 vs 候選盲順序配對；不只問「邊個靚」，亦問「點解」、「感到邊種氣質」。
3. **Recognition vs recall**：認出身份、提提示後辨認、之後自由回憶係三件事；隔時回憶需要實際跟進。
4. **Production**：第二位畫師嘗試根據設定重畫，另測正側背／動畫／3D 工序。

記清楚樣本數、招募偏差、作品熟悉度、展示條件、反對意見，**無數據就寫 `HUMAN_TEST_PENDING`**。無許可或無樣本都可用專業審美判斷，但要標明只係判斷。

## 審查結果四選一

`KEEP_ORIGINAL`／`PROMISING_BUT_UNVERIFIED`／`NEEDS_REDESIGN`／`BLOCKED_BY_CONSTRAINT`；每個判斷附上「會令結論改變嘅最低成本證據」。

## v9.1｜出圖後對抗式審查（硬性）

將「生成漂亮」同「改版有效」分開評。逐項對照 pre-render Change Ledger；漏咗改動就標 MISS、身份／圖案亂飄就標 DRIFT。**唔准喺出圖之後編造事前設計理由**。最少指出一項原版可能更好嘅方面；若背景、人物大小、光照／表情不同，說明比較被混淆。


## v9.2.3｜穿搭消失檢查

服裝候選評估之前，額外問：**有冇將原本有意義嘅穿法／不對稱／布料層次改成更泛用嘅標準搭配？** 若有，應指出失去嘅觀感，並同 `KEEP WEARING` 方案比較。

- 「更對稱／更整齊／更少皺褶／符合一般制服着法」只係觀察，**唔係改善嘅證據**。
- 「更不對稱／更個性化／更大形變」同樣唔係改善嘅證據。
- 觀感與身份評審要用正側背同正常觀看情境，並記錄穿法是否 `PRESERVED / CHANGED_AS_APPROVED / UNAUTHORIZED_DRIFT / UNCLEAR`。
