# Shape-First Design：主形體改版操作（v9.5）

呢份係可執行方法，不代表主角必須簡潔／華麗，不預設某個角色服裝要點改。

## 兩個完全不同的創作問題

- **修正**：原稿存在具體可觀察、會影響預定用途嘅問題。可以最小修改；不必硬做大幅造型差異。
- **設計探索**：原稿本身合格，但作者想試更好嘅方案。先提出新主形體假設；唔許虛構原稿有問題，亦唔許只換描線就當新設計。

## Shape Lever 候選庫（按任務選一個；唔係 checklist）

1. 衣長與腰線：短與長、是否露出腰部、上下比例。要交代側面與內搭。
2. 肩與袖：肩位、袖筒膨脹位置、袖口收口；對頭髮寬度同手臂空間嘅影響。
3. 下擺／裙擺：整體弧度、褶量分配、垂直／扇形／不對稱大面分組；要保留合理製作結構。
4. Layering：真正穿法、布料疊前疊後與因之形成的負形；不可把小飾物算作結構。
5. Color Massing：只用**已有**簽名配色，調整面積與聚散；大色塊有理據才換位置，唔等同新增圖案。
6. Material Massing：針織軟垂與挺身布料造成的體積關係；不能無故改變角色時代／類別語氣。

## 預先設計記錄（5 行就夠）

- `KEEP`：頭臉、髮型、主要識別、指定服裝件或圖案。
- `ONE MAIN LEVER`：一個可觀察主關係，寫出**前／後具體差別**。
- `OTHER CHANGES`：如有，必須係主槓桿嘅自然結果，不借機加細節。
- `LOSS / RISK`：原版可能比新方案更好的地方。
- `TEST`：同角度並排，先看形體，再看裝飾、陰影；必要時見側／背部。

## A / B / C 比較例（抽象，非角色專屬）

A `KEEP`：原版大衣遮住裙腰，提供鬆身、自然感。
B `SHAPE`：外套前擺略縮短，露出裙腰，但背擺保持，側面有連貫曲線。優點：腰線清楚；代價：失去原版包覆感。
C `WEAR`：保持外套長度，但換合理穿法讓內搭露出。優點：衣物關係新鮮；代價：改變角色穿著個性，並增製作複雜性。

呢啲改法係例子，唔代表每個角色都應露腰、加不對稱。若冇人類美感驗證，只可以話係可比較假設。

## 生成失敗樣態

- 新圖只係更靚的上色／更清楚影線：`NO_MEANINGFUL_DELTA`。
- 預計改衣長但模型加咗袖條紋：`UNAUTHORIZED_DECORATION`。
- 原稿外套簡潔，新圖無故加入一堆扣帶和邊線：`DESIGN_DRIFT`。
- 用戶要改圖，模型輸出分析海報：`FORMAT_DRIFT`。
- 主形體合理，但丟失原版簽名髮型／顏色／必留件：`IDENTITY_DRIFT`。
- 新形狀乍看特別，但側背無法接合：`CONSTRUCTION_FAIL`。

驗收標籤：`REJECT` / `UNVERIFIED_EXPLORATION` / `PASS_TO_HUMAN_REVIEW`（只有作者能批准正式版）。
