# v9.5 → v9.6｜修正「識得評論但做嗰陣做唔到」

## 診斷

v9.5 逐版加規則，存在兩種操作斷層：
- 出圖前以局部主形為起點，未強制全身審視；出圖後先分析色彩、比例同個性，令原因變成後設解釋。
- `Production simplification` 容易被誤判為 `Design improvement`；圖像模型執行偏移又容易被混同於壞設計構思。

## 今次實際修改

1. **重寫短核心**，統一執行順序：Brief → Whole-character scan → Precommit → Design/Production split → Render → Actual audit & design correction。
2. 全身掃描細分六大系統，特別加入所有配件、髮帶、後背及鞋襪嘅**色彩架構審視**。保留原色亦須有理據，唔假定「保留＝最優」。
3. 新 `Precommit`：生成前先寫兩個真正不同嘅假設，以及原版可能勝出嘅理由；禁止生成後逆向補理由。
4. `Design Gain` 與 `Production Fit` **獨立閘門**；即使動漫製作過關，角色吸引力仍要過關。
5. `BAD_CONCEPT` 同 `BAD_RENDER` 分流；發現美感冇改善，必須主動提出下一個具因果嘅設計假設，而唔單純結束。
6. 生成器專用 prompt 與設計報告分流，減少被誤讀成資訊板嘅風險。
7. 完整 v8 archive 與 v9.5 legacy refs 保留不變；測試角色只作獨立案例，唔寫入通用規則。

## 尚未驗證

文件規則與連結可檢查；**實際圖像生成是否遵守指令、角色美感是否改善，必須另以多種風格角色做盲比較驗證**。本輪唔聲稱已提高成功率。
