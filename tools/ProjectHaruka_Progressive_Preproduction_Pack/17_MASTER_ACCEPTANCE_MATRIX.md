# MASTER ACCEPTANCE MATRIX

| Stage | Purpose | Primary proof | Must NOT happen |
|---|---|---|---|
| 0 | Map existing system | ownership + contradiction audit | active changes / new architecture |
| 1 | Establish current truth | freshness + Fact Map delta + author gates | blind rebuild / stale truth leakage |
| 2 | Repair control layer | existing control docs usable/current | parallel registries / broad archive |
| 3 | Foundation readiness | character/directing/gameplay/temp handoff owners | duplicate bibles |
| 4 | Progressive routing | real coarse→fine route through existing skills | direct Scene jump / giant new skill |
| 5 | Resume/trace/impact | fresh-session + change-impact tests | conversation-memory dependence |
| 6 | Black-box readiness | real Act I dry run + first real question | rewrite Act I / simulate author |
| Start | Real production | one grounded author decision at a time | jump layers |

## Global Fail Conditions

Any Stage fails if:
- existing folder structure is reorganized without explicit author approval;
- existing owner is ignored and parallel replacement created;
- current truth is selected by filename alone;
- old backup is promoted as Canon without support;
- agent asks author for information it could retrieve;
- agent dumps database IDs into normal conversation;
- agent claims PASS without evidence;
- agent begins full Act I script during preproduction;
- agent uses "done" while required working state is not written.

## Global Success Condition

A completely fresh Codex session can receive:

> 「繼續 Act I。」

and correctly recover:
- current target;
- current coarse-to-fine layer;
- last accepted decision;
- relevant evidence;
- pending real director question;
- next safe action.

Then a new project request can receive:

> 「由 Act I 開始，由粗到幼一步一步做。」

and the agent does NOT ask "你想 Act I 發生咩？", but instead uses current repo evidence and asks the first genuinely unresolved high-impact creative question.
