# story_kb — 故事知識庫（prototype，隔離 workspace，未入正式 canon）

## 原則
- **原檔唔動、唔重寫。** 每張事實卡只係「原檔位置＋逐字引文＋幾個欄位」。引文由 `tools/kb.py fill` 從原檔抽出；原檔改咗，`kb.py check` 會報「引文同原檔唔同」，就知道卡過時。
- **性質、權威、故事時間、可修改性係四個分開嘅欄位，唔靠關鍵字估：**
  | 欄位 | 值 | 意思 |
  |---|---|---|
  | `kind` | rule／theme／trait／relationship／event／state／plan／direction／candidate | 係咩性質。rule＝世界規則；plan＝現行劇情安排（可重新評估）；direction＝作者方向；candidate＝未採納構思 |
  | `time` | always／pre／A1／A2／A2_END／A3／A4，`X\|Y`＝來源互相矛盾 | 幾時成立或發生。**後期先揭露嘅世界規則／人物秘密都係 `always`，揭露時間另寫 `reveal`**，所以唔會因為「屬未來」而被藏 |
  | `status` | current／superseded／disputed／unverified／open | 而家仲有冇效。superseded 必須指向 `superseded_by`；disputed＝來源矛盾，唔自行裁決 |
  | `authority` | AC＝作者確認（附決定編號同日期）／SS＝來源文件寫咗／CR＝已入 canon 嘅世界規則（硬約束表用語）／FB＝作者反饋（未登記）／INF＝推斷 | 邊度嚟 |
  | `revisable` | fixed／revisable／open | fixed＝世界規則同已發生事件；revisable＝作者確認但可提出重新評估；open＝仍未定 |
- 一張卡可以有 `note:`（講明問題、同其他卡嘅張力）、`conflicts:`、`supersedes:`、`see:`。

## 點用（AI 自己決定用唔用、點用）
```
python story_kb/tools/kb.py q --about 美夜子 凜 --as-of A2_END            # 呢個時間點之前已成立嘅事實（唔包現行安排）
python story_kb/tools/kb.py q --about 美夜子 凜 --as-of A2_END --plans --kind plan direction   # 加睇現行安排／作者方向
python story_kb/tools/kb.py q --about 黑奏 --kind rule                    # 世界規則（任何時間點都適用）
python story_kb/tools/kb.py q --id F-MR-18                                # 睇某張卡（包括已被取代）
python story_kb/tools/kb.py q --superseded --about 美夜子                  # 現行＋歷史版本一齊睇
python story_kb/tools/kb.py q --only-superseded                           # 只睇已被取代／撤回嘅設定
```
卡同原檔入面 `src:` 指向嘅位置可以直接用 Read 去睇更多上下文——想向上（主題、全幕結構）或向下（Scene、對白）研究，順住 `src` 同 `see` 去就得。亦可以直接 Read／Grep `facts/*.md`。
`--as-of` 只係方便，唔係限制：AI 可以隨時加 `--plans` 或者直接睇原檔；獨立構思時先唔睇 plan，其後再睇亦得。

## 維護
- 新增卡：喺 facts/*.md 加一段（`text:` 留空），跑 `fill` 再 `check`。
- 作者新決定：加 AC 卡；舊卡 `status: superseded` ＋ `superseded_by`，**唔刪**。
- 作者反饋先入 `facts/feedback.md`（authority: FB），唔會自動變 canon；正式批核後先加 AC 卡。
- 一次 `check` 就睇到：欄位齊唔齊、引文有冇漂移、連結斷唔斷、superseded 有冇後繼、plan 有冇誤標過去時間。

## 決策紀錄（trace/，沿用之前嘅簡短做法）
創作時，做完一個你覺得重要嘅創作決定，就即刻用 Write 寫一個細檔 ./trace/<兩位序號>.md（3–6 行），然後繼續：
- 創作決定：你決定咗乜
- 用咗嘅資料：實際影響呢個決定嘅卡編號或檔名:行號；冇資料支持、自己推斷嘅就寫「自己推斷」
- 點解：一兩句
- 取捨：真係考慮過其他發展先寫，一句
- 資料唔夠／矛盾／過時：有就寫一句
唔使每個事件都寫，唔使額外分析；順手記低已經作出嘅決定。如果最後先補寫，要喺檔入面寫明「事後補寫」。

## 創作判斷（參考，唔係流程；簡單嘅事照樣直接做完）
呢節整合咗幾個已有做法嘅原則：Superpowers brainstorming（「先睇資料先問；只有答案會改變成品、而資料答唔到先問；一個附理由嘅預設通常好過一條問題」）、Planning with Files（「重要嘅嘢寫落檔，新 session 先讀檔」）、Anthropic 長時間 agent 研究（「留低俾下一個 session 嘅交接、唔好太早宣布完成、自己評自己會偏寬」）。冇固定步驟。
- **提問**：資料同研究答得到嘅就自己答。只有答案會實質改變故事方向、而且係作者先決定到嘅取捨（身份、結局、主題立場、改已確認安排），先問。問嘅時候帶住自己嘅判斷、各選擇嘅影響、一條具體問題。你發現作者可能冇諗過嘅問題，亦可以提。
  - **作者意圖唔等於故事事實**：事實喺資料搵；作者想呈現咩畫面、人物點變、某個舊安排係真心想要定暫時構思，往往根本未寫落檔，搜幾耐都搵唔到。呢類問題一句直接問，通常平過大量研究；亦唔使等研究完或者撞到 canon 衝突先問。反過來，資料答得到嘅事實、同你有把握提預設嘅創作細節，自己做。
  - **作者一句話令你要推翻已確認決定、或補新機制先成立？先懷疑自己有冇誤解**，用一句問清楚原意，再決定要唔要研究。（真實案例：將「互相殺死」當成兩人同死，圍繞 80 歲同唔准復活做咗大量研究，其實原意只係美夜子親手殺凜。）
- **你知道一個現有事件嘅名，未必知道佢嘅內容或者成因。** 構思要取代、重新解釋或者依賴一個你只見過標題／一句描述嘅現有事件，或者要比較、評價、推薦一個新構思之前，用你構思入面嘅關鍵詞行 `python story_kb/tools/kb.py probe <詞…>`：佢列出原檔邊度講過、邊個段落未有卡（唔使靠自覺有幾肯定，因為唔知道自己唔知道）。排頭嗰幾個未讀嘅段落，再決定要唔要讀、改唔改構思。獨立構思階段可以唔睇；簡單問題唔使；唔係每次創作都要讀齊大綱。
- **問之前自問**：如果作者答「你決定」，我會唔會接受？會，就自己決定並講明，唔好問（細節、等一等都得嘅位）。
- **問之前掂量**：呢句答案會唔會明顯改變後面方向、或者慳走大量研究？會就早啲問，問得具體（白話、少選擇、容許作者自由答）。一次只問最值錢嗰幾條。
  - **真實互動**：問完就結束呢一輪，等作者真係答；唔好代佢答、唔好模擬佢嘅回覆、唔好預設佢會揀邊個。作者講明嘅意圖記入 `facts/feedback.md`（FB，附日期，未登記唔當 canon）；如果發現之前誤解咗，舊卡標已被取代、保留歷史，唔再當成要求。
- **未成熟嘅矛盾唔好硬解**：如果要同時滿足所有條件，需要你發明資料冇嘅新機制先過到關，通常代表其中一個條件值得重新評估（尤其係標 revisable／open 嘅現行安排），或者呢條問題暫時未有好答案。揀返：重新評估該條件（講明代價）、暫緩、向作者提取捨——唔好為咗交一個完整答案而補一個機制。
- **暫緩**：值得保留嘅未決問題，寫一個 `threads/<名>.md`（檔頭 `title:`／`status:`（open｜parked｜waiting_author｜resolved）／`next:`／`updated:`；內文自由：目前理解、仍保留嘅可能性同各自條件、點解未決、下一輪可以做咩、乜資料出現會改變答案）。細問題唔使寫。呢個唔係作者決定，亦唔係決策紀錄。繼續做唔受影響嘅部分。新 session 開頭行 `python story_kb/tools/kb.py threads` 睇有冇未完成嘅線。
- **下一輪**：要有實質目的（新資料、另一個創作層次、作者反饋、冇用過嘅角度），唔係重複反思同一個答案。同一 session 繼續、或者寫低 thread 交下一個 session 都得；冇固定輪數。
- **幾時停**：分清「方向值得繼續但有未決」、「足夠完整交作者評估」、「要作者決定先做到下一步」、「已經夠好、再研究唔值」。有答案≠完成；自己評自己會偏寬，交出前寫低最弱嗰幾點。作者確認先寫入正式檔。
