### 四類因素拆分

1. **知識表示／組織**：typed node/edge 可以把「人物—事件—規則」及「作者決定」明寫成可查關係，並為每條 edge 附來源。但這 9 條邊是人手定義；目前錯誤或遺漏率由整理者承擔。Graphiti 本身不會替作者判定草稿、Canon、意圖或故事因果。
2. **原文覆蓋**：graph 有 7 段原文；正式 KB 對照只看 F-KH-25 一張卡，但卡其實引用同一 outline 全段，且包含更多敘事細節。圖能跨檔整理六個主題，部分是因多索引 6 段來源，非因圖本身。`probe` 對同一查詢族曾有 567 個段落命中，顯示召回範圍大但噪音多；此數字不等於輸入模型的 token 數。
3. **檢索／關係擴展**：BM25-only 對精確長句可命中，對單一人物名及 paraphrase 不穩。測試沒有提供自然語意向量模型，也未證明 Graphiti BFS 對中文關係查詢帶來多跳收益。簡單關鍵詞掃描會列出很多候選，但沒有排序為可信答案。下一輪如試語意向量，需先找到可離線、支援中文且不改變隱私邊界的選項。
4. **AI 使用方式**：本輪沒有讓外部 LLM 自動抽取或回答；亦沒有同一模型、同一 prompt 的隨機化 A/B。工具可以輸出短 edge 和原文 episode，但它是否能讓 AI 自然使用、是否降低錯誤／token，尚未被證明。

## 舊卡與版本風險

`F-KH-25` 把「時長矛盾／待 Act IV 核實」保留在 status／authority/note；note 同時已提 CDL-430 的「現實數日、主觀二十年」。樣本來源 `CANON_DECISION_LOG.md:6` 另有作者批准條目，時間線 `04_timeline_canon.md:302` 亦記相同時鐘。這表示卡片局部狀態可能落後於來源；本研究沒有改卡，也不自行把卡標籤改成已解決。

Graph edge 可額外存決定編號／日期，但不會自動發現卡片狀態已過時；需一條「Canon 決定變更 → 搜尋受影響卡／邊 → 作者審核」的同步工作流。

## 一次非 Canon 故事創作檢查

### 任務

在已有故事上下文下，提出一個能挑戰現有「蜜月期困境」草稿的替代宏觀處理；保留創作自由，測試能否運用人物／規則／時間／版本資料；不寫回正式故事。

### 檢索輔助的 DRAFT 概念（本次 AI 探索產物）

**「選擇的測試」版本**：保留家庭早餐般的表層日常，但把場景節奏由「違和細節愈積愈多」改成連續的小選擇測試。晴香先選擇不喝湯、轉而做一件不合那個房間期待的小事；房間的回應逐次暴露出問題不在環境夠不夠幸福，而在她能否決定自己怎樣回應。中段與夕在外面長期守望交叉剪接，但不暗示晴香知道他的行動，也不宣稱兩條線有直接因果。高潮可暫時把「繼續掙扎」與「停止掙扎」都呈現為有代價的選擇：世界規則只明確支持停止掙扎讓連結自然回復、強行掙扎會加速磨損；它未決定晴香停止掙扎是否知道、是否會令她逃出困境。結尾留在她重新取得選擇能力的跡象，而非代替作者決定逃脫機制。

### 檢查結果與限制

- **理解／錯誤控制**：這段構思有區分二十年主觀經驗與 Act IV 現實數日；夕／晴香是交叉剪接，不擅自令晴香得知夕的行動；明確把線的自然回復機制與「逃出監獄」分開。這是本次生成者直接閱讀背景及報告後的結果，不能證明 Graphiti 導致準確。
- **自然取得知識**：構思確實使用了人物線、時間決定及連結線規則，但測試者預先已見過來源摘要；並非盲式從 Graphiti 查詢結果自動組 prompt。故「自然取得」未測。
- **找出類似劇情**：概念刻意從現有陽光房間／家庭早餐／態度剝奪出發，故不是新鮮度盲測；工具層卻有一個同題 BM25 零命中的負例。表示故事作者可能靠先驗上下文避開重複，但檢索本身仍未可靠做到。
- **挑戰原大綱／自由創作**：改變場景推進機制、將設定留作草稿、暫不決定逃脫條件。這是一個可供作者挑選或否決的發想，不是「更好」的結論，亦未測到多輪續寫能力。
- **修改連鎖影響**：概念識別出「掙扎會磨損／停止會自然回復」的直接規則，但沒有足夠來源推演對逃脫、夕行動、全作結局的下游因果。任何此類連結仍要回到來源／作者決定查證。
- **整體 Token**：此輪沒有 LLM API／生成模型 token。未取得公平的同模型 A/B token 數。Graph 結果最多可輸出一條 fact＋引用 episode；要保證可審核仍需讀原文。未證明整體 token 減少。

## 長期修改／局部更新試驗

原型把 CDL-430 episode 的文字加一段 fixture edit 後重新 `save`，讀回確認 episode 文字更新；相關 edge 的 fact 仍是舊文字，引用的 episode id 未變；Relate round-trip 的 `episode_metadata` 為 `null`。因此：

- Graphiti/Relate 儲存能力可用，但這個 driver／SDK 沒替此工作流做來源檔 watcher、hash/diff、卡片狀態判斷或相關 facts 重抽取。
- 修改來源後要自行找出所有引用該 episode 的 edge、判定是否仍有來源支持、更新／失效 edge、保留舊版本，再重建只受影響的 facts。刪除來源亦要清理孤立節點／edge。須另建 source manifest 和同步器，否則舊圖會靜默保留過時結論。
- 事件／關係一旦人工抽取，改原文局部段落後的複核成本仍可能高於現有 `quote drift` 檢查。保守流程需人手審核抽取與失效結果；不應自動把新抽取內容升格為作者決定。
- LightRAG 實作具有依來源 id 追蹤及 purge/recovery 路徑，增量刪除概念較完整；仍需抽取 LLM、來源同步和作者狀態補層。Graphiti 的 temporal edge validity 並不等於來源版本管理。

## 本輪可支持的結論

候選圖能把已整理關係和來源引用放在同一個索引，對作者決定／跨檔關係很有表達力；但此次 CJK BM25 檢索有 3/5 查詢無 edge、1/5 僅 episode、1/5 edge+episode。實際故事創作與錯誤率／自由創作／Token 的因果改善未證明。最重要的維護缺口是：來源更新不會使依賴事實失效，metadata 與版本狀態亦非自動完整保存。
