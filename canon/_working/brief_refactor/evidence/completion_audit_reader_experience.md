## A. Glance reader（只睇標題／bold／圖表／card，唔讀長prose）

### 做得好嘅部分
- **七個核心法則章節**（`id="laws"`, line 5807-5946）係全文最適合掃視嘅設計：一開首有 `law-causal-flow` 因果鏈圖（line 5814-5830，01 心之器受傷 → … → 07 存在向屍骸滑落），跟住有 QA card grid（line 5860-5873，Q&A 形式一眼睇晒六條核心問題）。單靠呢兩個視覺元素，讀者已經可以完整掌握呢章主結構，唔使落去讀詳細版（detail 收埋喺 `<details>` 摺疊區）。
- **遊戲系統設計章節**（`id="game"`, line 11065+）全部用 card grid + emoji icon + bold 小標題（⚔️電影化戰術戰鬥／🔗敘事玩法融合／🏙️無縫探索），glance 讀者可以完整攞到三支柱概念。
- **故事章節**（`id="story"`）每個階段都有「story-strip」beat card（例如 line 9268-9366），每張card係「bold數字標題 + 一句概要」，詳細內容摺疊喺 `<details>展開原本詳細文字</details>`（line 9381）入面——呢個結構本身係為 glance/scan 讀者度身訂造。
- **人物關係地圖**（`id="rels"`, line 8952+）用 SVG 家族樹 + 彩色分類 box（同一身體 / 血緣家族），glance 讀者可以睇圖秒懂關係網絡。

### 有問題嘅部分
- **世界觀速覽章節**（`id="world"`, line 5044-5805）: 呢章雖然有 table 同 card，但「奇蹟」「Alpha/Beta 線」「解離兵器 vs 裝置魔法少女 vs 真正魔法少女」三條路線之間嘅關鍵區分（邊個先算「有護甲」、解離兵器係唔係第三條獨立產線）淨係喺 `reader-warning-note` 同 `dedup-note` 嘅純文字段落入面講清（line 6165-6170），冇被獨立bold或者做成圖表節點——只睇 card 標題同 lane 標籤（「真正魔法少女」「裝置魔法少女」「解離兵器」）嘅讀者，好大機會誤讀成三條平行、互斥嘅產線，同文件想更正嘅誤讀完全一樣（見下方文件自己承認嘅 "Canon 修正" note，line 6168-6170）。
- **角色卡（`id="chars"`）**：每張char card 上半部（badge、name、日常外在/內在隱藏標籤、「身份說明」box）確實可以畀 glance 讀者掌握角色基本身份。但角色最重要嘅心理機制（例如晴香嘅「誘惑——拯救者情結底下唔敢承認嘅自私核心」line 6908、「壓抑稅」line 6909、凜嘅「三段式心理」line 8092）全部埋喺無 bold、無視覺break嘅長段落入面，只有段落開頭一個詞被 `<strong>`（例如「壓抑稅——自我盲點嘅精準機制」），跟住成段密集文字冇再有任何視覺重點——glance 讀者只會攞到一個標籤詞，完全唔知呢個機制實際運作方式，等於呢部分內容對佢哋嚟講係空白。

**小結**：文件入面「世界機制／遊戲設計／故事骨架」三類內容做到真正 glance-friendly；但「角色心理深層機制」呢一類內容，設計上仍然依賴長文閱讀，glance 讀者會完全錯過。

## C. Continuous reader（由 `id="what"` 開始逐段落實際讀落去）

### Text wall（一大段密集prose冇分段/冇視覺break）
用行距/字數掃描全文，`<p>` 內文字超過300字元嘅段落有 36 個，集中喺兩個區域：
- **角色卡區（line 6800-8500）**：最密集，例如晴香卡 line 6907-6911 五段連續嘅巨型段落（每段 300-600 字元），單一段落入面塞晒「Act I 冇面具冇隱藏創傷」「誘惑——拯救者情結底下嘅自私核心」「壓抑稅」「經理人——被幫助者的反骨」「二十年守望——為自己喊」五個完全獨立嘅心理機制/劇情節點，冇任何段內分項、冇 bullet、冇小標題break。凜卡 line 8091-8095 同樣現象，單段塞入「三段式心理」「紅線背後嘅渴望」「意識清零一刻」三個獨立概念。
- **故事章節嘅展開全文（line 9700-9850）**：例如 line 9823（刑思三重攻擊嘅完整描述）、line 9841（膠布哲學第三層揭露），呢啲段落密度同角色卡相若。

呢啲段落唔止長，仲同時引入多個新術語（拯救者情結、絕對共感視界、壓抑稅、靈魂延遲、Unit 00-Null、護甲、執念錨點……），連續讀落去嘅認知負荷非常高。

### 重複感（讀過一次，第二次又讀多次）
最明顯例子：

2. **「維多利亞天使／偶像唔係官方制度，晴香係經理人個別經營嘅例外」**——呢句disclaimer 喺文件入面至少出現六次以上，幾乎逐字重複：市民眼中的世界（line 5152-5153, 5157-5159）、日區district card（line 5178）、world-idol-origin card（line 5281）、凜嘅角色卡（line 8079）、故事第一階段（line 9344）、故事第二階段前置（line 9464）。單一次讀者理解咗之後，每次再遇到都要重新確認「哦又係嗰句disclaimer」，感覺像文件對自己嘅讀者冇信心，驚讀者唔記得。

## D. Deep-reference reader（跳頁模擬，唔返去讀前文）

### 例1：角色卡——凜（`id="c-rin"`, line 8028）
直接跳嚟呢張卡：**身份說明box**（line 8075-8078）本身已經係自足嘅——交代咗「凜點解會由死變返生」「光環處決」「刑思操控維多利亞之淚還原肉體」「記憶模糊係復原副作用」，並列出咗指向相關角色（`#c-keishi`、`#c-miyako`、`#c-haruka`）嘅連結。單憑呢個box，唔使返去讀前文都可以理解凜嘅基本處境。**但**再落去嘅深挖段落（line 8091-8095）開始假設讀者已經識「護甲」「靈魂距離光譜」「Unit 00-Null」「執念錨點」等術語，呢啲詞喺凜卡入面冇本地解釋，要跳去「魔法少女設定 → 起源三條路線」（line 6163+）或者「七法則 → 三位一體光譜」（line 5931+）先搵到定義。**結論**：身份層面夠自足，但機制/術語層面唔夠，要再跳一次先搵齊料。

### 例2：世界規則——情緒守恆定律（`#law-conservation`, line 5883-5889；附錄補充版 line 11709-11716）
如果讀者直接跳去**附錄版**（line 11710-11716）：card開首第一句就寫明「基本定義見上面〈七個核心法則〉；呢度只補一個附錄層先有嘅隱喻角度」，然後用「Alpha 線是債權人」呢個獨立比喻把整個概念講得自足、易明，唔需要返去讀七法則先明白呢張card想講咩。**呢個係全文deep-reference設計嘅最佳範例**——它主動承認自己嘅依賴關係、給連結、然後仍然提供一個完整可讀嘅獨立內容單位。如果讀者跳去嘅係主定義版（`#law-conservation`, line 5883），內容同樣簡短自足（3句講完機制），問題唔大。

### 例3：Timeline event——sacrifice-truth（`id="tl-sacrifice-truth"`, line 10944-11043）
呢個節點本身組織良好：有標題「崩潰觸發點」、雙分支圖（類Alpha分支 vs 新Beta分支）、每格都帶連結返去相關角色卡，仲有「校訂備註」「pending-approval」tag清楚標示「Act IV Outline 全書仲未開始正式設計，此節僅供理解走向」——呢個透明度好高，深度連結讀者唔會誤將呢段當成已批核canon。**但**同一區域（line 9871-9880，故事第四階段展開全文入面「廢墟戰場介錯」場景圖）出現一個結構性缺陷：呢張圖冇用返其他場景圖統一嘅 `class="scene-desc-btn"` + `data-title` + `data-desc` 模式，而係將成段場景劇本文字（約400字）直接塞入 `alt` 屬性——即係話呢張圖大機率**冇彈出modal功能**，讀者點擊佢唔會攞到其他場景圖同等嘅互動深讀體驗，形成同文件其他部分不一致嘅deep-link斷點。

**D 部分小結**：文件入面「身份說明box」「附錄補充卡」「timeline校訂備註」呢類刻意設計嘅deep-entry-point做得幾好，普遍有self-contained摘要+連結返主要概念嘅習慣；但一旦落去更深層嘅心理機制分析段落，就會裸露大量未本地解釋嘅術語，逼深度連結讀者再跳第二、第三次先夠料。另外圖片modal系統喺個別位置（起碼一處已確認）冇跟返標準模式，形成功能性不一致。

## 總結（四種模擬讀者共同指向嘅結論）

1. **文件入面兩種完全唔同嘅寫作模式並存**：世界觀/系統/遊戲設計用card-grid+diagram（對 glance/scan 讀者友好），角色/劇情深挖用長篇密集散文（對 continuous 讀者不友好），兩者之間冇一致嘅閱讀節奏過渡。
2. **關鍵術語/免責聲明重複次數過多**（維多利亞天使非官方制度、晴香創世起源），顯示文件對自己嘅讀者記憶力冇信心，每次提到相關概念就重新解釋一次全套，加重continuous讀者嘅重複感。
3. **Sidebar/scan層面嘅入口密度唔均**：世界觀、結局、主要角色搵得到、搵得快；但「Act III」呢類劇情分期同「魔法屍骸」呢類跨章節概念，冇集中入口，要跨最少3張card拼湊。
4. **Deep-reference設計有好範例（附錄card、身份說明box、timeline校訂備註），但唔一致**——角色卡深挖段落大量使用未本地解釋嘅術語，個別場景圖modal功能缺失。
5. 仍存在未清理嘅品質缺陷（簡體字/錯字、內部編輯校對筆記混入讀者可見嘅data-desc）。

呢份audit冇評估「呢啲問題係咪master task範圍」，淨係按作者要求老實報告依家實際閱讀落去嘅狀態。
