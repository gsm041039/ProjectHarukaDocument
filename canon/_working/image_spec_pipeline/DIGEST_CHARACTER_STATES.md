# DIGEST：角色外觀狀態軸（Character Visual State Digest）

**建立日期**：2026-07-17
**用途**：供 image-spec pipeline（Agent A / Agent B）查詢每個角色喺故事推進中經歷嘅「視覺上有變化嘅階段」，避免每次寫 spec 都要重新爬全份 canon，亦避免鎖死可能已過時嘅完整外觀描述。
**規則依據**（PIPELINE_INSTRUCTIONS.md §3）：
- 本檔**唔記錄完整外觀描述**（唔寫「黑長直髮、著XX洋裝」呢類細節）——基準外觀一律以 Reference Image 為準，冇 reference image 就標 `[NO_REF]`。
- 本檔只記錄**狀態軸**：每個角色有邊幾個外觀/形態階段、每階段喺邊個 Act/Phase 生效、觸發呢個變化嘅劇情點、階段之間變咗啲乜（delta）。
- Spec 撰寫時角色描述應寫成「狀態標記 + 本場景相對變化」（例：「操（Body Horror Stage 2a：外表仍完美，掉牙初期）」），唔好抄呢度以外嘅細節外觀落 spec。
- 來源優先序：`canon/03_characters/*.md` 為準；`IMAGE_PROMPT_SPEC_FINAL_72_COMPLETE.md`（下稱「舊72圖檔」）只作參考輔助，若兩者矛盾以 canon 為準並喺下面標記矛盾。

**方法論說明**：舊72圖檔共 8625 行，本次以 grep 章節標題（`## 圖N：...`）方式掃描全份，抽出所有涉及本 digest 11 位角色嘅場景標題與 Act 標記，用嚟交叉核對 canon 已有嘅階段設計是否吻合；未逐行精讀全部 200+ 段落內文。掃描範圍內未發現與 canon 直接衝突嘅角色狀態描述——舊72圖檔嘅場景（例如「美夜子Glitch Form首次」「凜的雙面形態」「操の被迫報串」等）與 canon 現有階段設計一致。如後續逐 beat 撰寫 spec 時 Agent A 發現舊72圖檔內文與 canon 有具體字眼衝突，須在該 beat 事實清單標記並回報，唔可以 silent resolve。
